Why Restrict on the three Property foreign keys?
Property has three FKs. SQL Server refuses to create a table with multiple cascade delete paths — the migration fails with "may cause cycles or multiple cascade paths." Restrict avoids that, and is also correct behaviour: you should not lose properties because someone deleted a city. Cascade is safe on the child tables because images and appointments are meaningless without their property.

Identity Tables

ASP.NET Identity adds seven more tables automatically. They handle login and roles, and are not linked by foreign key to the business tables above.

TablePurpose
AspNetUsersAccounts — email, hashed password, FullName
AspNetRolesAdmin, Agent, Customer
AspNetUserRolesWhich user has which role (many-to-many)
AspNetUserClaims, AspNetRoleClaims, AspNetUserLogins, AspNetUserTokensCreated by Identity; unused in this project
Expect this question: "Why is there an Agents table and an Agent role?"
They are different things. The Agents table holds display data — name, phone, agency — used in the property dropdown. The Agent role is a login account with permission to create properties. We kept them separate to keep the model simple; linking them would mean adding a UserId column to Agents.

Table PropertyType {
  Id int [pk, increment]
  Name varchar(60)
  IsActive bool
}

Table City {
  Id int [pk, increment]
  Name varchar(80)
  Governorate varchar(80)
}

Table Agent {
  Id int [pk, increment]
  FullName varchar(100)
  Phone varchar(20)
  Email varchar(150)
  AgencyName varchar(150)
}

Table Property {
  Id int [pk, increment]
  Title varchar(200)
  Description text
  PropertyTypeId int [ref: > PropertyType.Id]
  CityId int [ref: > City.Id]
  AgentId int [ref: > Agent.Id]
  Address varchar(300)
  Price decimal(18,2)
  Area int
  Bedrooms int
  Bathrooms int
  ListingType int
  Status int
  IsFurnished bool
  MainImageUrl varchar
  CreatedAt datetime
}

Table PropertyImage {
  Id int [pk, increment]
  PropertyId int [ref: > Property.Id]
  ImageUrl varchar
  DisplayOrder int
}

Table Appointment {
  Id int [pk, increment]
  PropertyId int [ref: > Property.Id]
  VisitorName varchar(100)
  VisitorPhone varchar(20)
  RequestedDate datetime
  Status int
  Notes varchar(500)
  CreatedAt datetime
}
